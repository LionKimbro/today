We're going to kick off #07 with a special model:

                                  (bounded present state)  (canonical, world model)
				          \                 /
  main/tkinter <== Special Queues ==> reducer-core ----- mem
                                                  \      /
                                                MOBILE STACKS
  The "Special Queues" are for just                 \  /
  relaying tk events to the reducer-core,            \/
  and relaying tk commands to the main/             disk
  tkinter thread.
  
  Mobile Stacks are NOT used for communication between main/tkinter,
  and the reducer-core thread.

  Mobile Stacks are issued from reducer core effects,
  and issue to reducer-core events.

  The Law:
-------------------
Tk → Core queue: normalized semantic UI events only; never raw Tk objects or widget references.
Core → Tk queue: declarative Tk commands/snapshots only; never arbitrary callbacks from another thread.
Reducer commits next_state before processing its effects.
Effects may start Mobile Stacks.
A returning stack does not start another stack while active. Its Core handler queues a normal result event, then completes the stack.
Mem remains the canonical world model; the Core holds only bounded present/on-screen state.
